# 종합 판단 루브릭 (Synthesis Rubric)

`backlog-discover`의 **P6 종합 판단** 단계가 사용하는 판정 기준. 도출된 항목 더미를
**진단 → 중요도 → 단계 구성**으로 접어 사람이 결정할 수 있는 형태로 만든다.
개념적 배경은 [playbook.md Part D](playbook.md) 참조.

---

## ① 현재 상태 진단

이번 실행에서 실제로 관찰한 것만으로 **네 문장**을 쓴다. 관찰이 없는 축은 "이번 주기 미관측"으로 남긴다 — 추측으로 채우지 않는다.

| 축 | 쓰는 것 | 근거로 삼는 활동 |
|---|---|---|
| **비전 대비 지점** | 선언된 비전 중 이미 도달한 것 / 아직 빈 것 | `vision-gap`, `roadmap-decomposition`, `dogfooding` |
| **시장 내 자리** | 누구를 위한 것으로 선택받고 있는가, 그 서술이 여전히 참인가 | `positioning-review`, `benchmarking`, `usage-analytics` |
| **도메인 적합성** | 이 주제 영역의 현재 이론·실무·규범에 비추어 제품의 접근이 여전히 타당한가 | `research-scan`(도메인 축), `domain-practice`, `benchmarking`(도메인 모델링 비교) |
| **내부 체력** | 부채·리스크·처리량이 감당 가능한 수준이고, 이미 가진 것이 관리되고 있는가 | `stewardship-check`, `code-audit`, `security-compliance`, `tooling-development` |

**도메인 적합성 축은 생략할 수 없다.** 이번 주기에 도메인 축 활동이 하나도 돌지 않았다면 "이번 주기 미관측 — 다음 실행 예정: {날짜}"라고 명시한다. 조용히 빼는 것은 "도메인은 이미 정해졌다"는 미검증 가정을 사실처럼 만드는 일이다.

마지막에 **한 문장 요약** — "이 제품은 지금 〈상태〉이며, 다음 한 걸음은 〈방향〉이다."
이 문장이 이번 제안서 전체의 논지가 되고, 중요도 판정은 이 논지에 대한 기여로 매겨진다.

---

## ② 중요도 판정

각 항목을 **세 요소로 채점(1~5)하여 가치 점수**를 내고, **비용·리스크는 배치에만** 쓴다.
비용이 큰 항목이 가치가 낮아지는 것은 아니기 때문에 점수에 섞지 않는다.

| 요소 | 5 | 3 | 1 |
|---|---|---|---|
| **비전 기여도** | 진단의 "다음 한 걸음"을 직접 전진시킴 — 인용한 비전 문구가 있음 | 비전과 정합하나 간접적 | 비전과 연결을 설명할 수 없음 |
| **철학 정렬** | P5의 [philosophy-alignment-guide](../../mindset/references/philosophy-alignment-guide.md) 4차원 평균을 그대로 사용 (재계산하지 않음) | | |
| **증거 강도** | 아래 표 참조 | | |

**가치 점수 = (비전 기여도 + clamp₁₋₅(철학 정렬) + 증거 강도) / 3**

철학 정렬은 **1~5로 클램프해서** 넣는다. 정렬 가이드의 레드플래그 보정(−1/−2)이 적용된 값은 1 미만이 될 수 있고, 그대로 평균에 넣으면 다른 두 요소와 척도가 어긋난다. 클램프하되 **레드플래그가 걸렸다는 사실은 항목 비고에 남긴다** — 점수에서 사라진다고 사안이 사라지는 것은 아니다.

### 증거 강도 등급

| 등급 | 근거의 성격 | 예 |
|---|---|---|
| 5 | 직접 실행 증거 | 도그푸딩 run-evidence, 관리 점검에서 실제로 실행한 명령의 출력, 텔레메트리 수치, 재현된 결함 |
| 4 | 반복·외부 확인 신호 | 동일 요청 2건 이상, CVE 고지, 의존성 EOL 발표 |
| 3 | 정적 관찰 | 코드/문서 스캔 결과, 벤치마킹 비교표, 논문·표준 문헌 |
| 2 | 단일·간접 신호 | 이슈 1건, 한 사람의 언급, 추정된 사용 패턴 |
| 1 | 사고 실험 단독 | 프리모텀·인버전·크로스도메인 차용 등 창발 계열만으로 나온 항목 |

**증거 강도 1~2 항목은 '지금'에 배치할 수 없다.** 창발 항목이 중요해 보인다면, 그것을 바로
올리는 대신 **증거를 만드는 작업**(해당 시나리오의 도그푸딩, 계측 추가, 사용자 확인)을 선행
항목으로 세우고 본 항목은 '다음'에 둔다. 창발 계열은 가설을 만들고, 배치는 근거가 결정한다 —
이것이 "발명 금지" 규율이 판정 층에서 작동하는 방식이다.

### 비용·리스크 (1~5, 높을수록 비쌈)

구현 규모, 블래스트 반경(공개 API·데이터 모델·의존성 변경 여부), 되돌리기 비용을 함께 본다.
**되돌리기 어려운 항목은 비용 4 이상**으로 본다 — 규모가 작아도 그렇다.

## ③ 단계 구성

가치 × 비용으로 **지금 / 다음 / 나중** 세 지평에 배치한다. 지평은 **순서**이지 일정이 아니다.

| | 비용 낮음 | 비용 높음 |
|---|---|---|
| **가치 높음** (≥ 3.5) | **지금** | **다음** — 반드시 더 작은 단위로 분해한 안을 함께 제시 |
| **가치 낮음** (< 3.5) | **다음** (여유 시) | **나중** 또는 기각 후보 — 왜 지금 하지 않는지 한 줄 |

### 배치를 덮어쓰는 제약

1. **의존 우선 (하드 제약)** — 선행 의존이 있는 항목은 선행보다 앞 지평에 놓을 수 없다. 점수보다 우선한다. 항목마다 `선행: {항목 또는 없음}`을 명시한다.
2. **순환 의존은 그 자체가 발견** — A↔B 순환이 나오면 배치를 강행하지 말고 "결합도 문제"를 별도 항목으로 세운다.
3. **증거 하한** — 증거 강도 1~2는 '지금' 불가 (위 참조).
4. **축 편중 경고 (세 축 모두)** — '지금'이 한 **가치 축**(비즈니스/기술건전성/사용자요청)으로만 채워지거나, 이번 실행 전체가 한 **탐구 축**(SW기술/도메인전문)으로만 채워지거나, 최근 3회 `history[]`가 **시간축**(과거/현재/미래) 중 미래가 1/4 미만이면 제안서에 편중을 명시한다. 자동으로 재배치하지는 않는다 — 사람의 판단 재료다. 탐구 축·시간축 편중에는 그 축이 왜 비었는지(활동 미도래 / 신호 부재 / 미시도)를 함께 적는다.
5. **되돌리기 어려운 항목은 Discussion** — 비용·리스크 5 또는 공개 계약 변경을 수반하는 항목은 지평과 무관하게 `Discussion 필요`로 표기한다.
6. **지평은 비어 있을 수 없다, 이유 없이는** — 지금/다음/나중 세 지평 각각 최소 한 항목이 있거나, 비어 있다면 왜인지 한 줄로 명시한다 ("스킵된 활동" 섹션과 같은 무침묵 규율). '나중'일수록 항목을 방향성 수준(추상적)으로 적어도 되고, '지금'일수록 구체적이어야 한다 — 항목 자체의 상세도 지평에 따라 달라진다는 뜻이지, 지평을 채우기 위해 근거 없는 항목을 만들어도 된다는 뜻이 아니다 (①의 발명 금지 규율은 그대로 적용).

### 금지

- 사이클 번호, 날짜, 기간 추정("2주", "3사이클") — 지평은 순서만 표현한다.
- 메이저 버전을 암시하는 묶음 — 분해 가능한 최소 단위로 제시한다.
- '지금' 지평이 로드맵에 자동 반영된다는 서술 — 어떤 지평도 자동 병합되지 않는다.
